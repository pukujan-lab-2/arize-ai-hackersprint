Rebuilt on main (after #12 ruff/mypy, #13 contracts, #14 deploy). Includes the Fish TTS hotfix that was uncommitted on the Pro (server.py, limits.py `FISH_TTS_PER_HOUR`, tests/test_tts_fish.py).

- **Chain**: Fish (8s, cap-aware, falls through on 401/402/429/5xx/errors) -> ElevenLabs (if keyed) -> **Kokoro** local service (`KOKORO_URL`, 10s, `KOKORO_TTS_PER_HOUR`=1000) -> `429 {fallback:"browser", provider:"browser"}`. `X-TTS-Provider`/`X-TTS-Cache` headers; `/api/tts_ts` keeps `{audio_b64, chars, starts}` (+`provider`, `duration_s`; Kokoro gets evenly spaced starts).
- **Queue**: single worker, dedupes identical in-flight lines, interactive request > first 2 tour steps (fast start) > rest of tour (batch, playback order). `POST /api/tour/prefetch`, `GET /api/tour/{run_id}` with per-step `clip_key, provider, duration_s, cite_ids, refs, node_ids, coords, phase, ready`.
- **Cache**: key `sha256(provider|voice|text)`; L1 local SQLite + mp3 (`.tts_cache/`), L2 shared Octo workspace (managed Postgres via its SQL API). Cache checked before any provider call; hits don't touch caps.
- **Schema**: `schema/` models + `migrations/0001_init.sql`, `0002_tour_step.sql`, `schema_version` table in Octo, `schema.lock.json`; app checks version on startup (`/api/health` `data_schema`), deploy applies pending migrations.
- **Health**: `tts: ["fish","kokoro","browser"]`, `fish`, `kokoro`, `tts_cache`, `data_schema`.
- **Kokoro service**: `tools/kokoro/` (kokoro-onnx FastAPI wrapper, py3.12 venv, launchd `com.precedent.kokoro`).
- **Frontend (minimal)**: map tour speaks with browser speechSynthesis on fallback instead of silent captions; map page prefetches the whole tour (summary + stops).
- Tests first: test_tts_chain, test_tts_queue (tour + replay = one Fish call per line; in-flight dedupe; order; Octo shared layer; Octo down), test_schema.
