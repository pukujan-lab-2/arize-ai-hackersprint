## What changed
- Mobile single pane (static/v2.html, static/v2.css, static/v2.js): Answer/Map buttons (data-pane, mobile-only, data-mobile-pane on .v2-main) switch ONE full-height pane at max-width 899px between the header and the sticky bottom composer. Desktop Split unchanged.
- Panels from the top: Sources/Legend/Follow-ups (and Run info) open from the top into that same pane on mobile (no bottom sheets); close returns to Answer. Only one panel at a time.
- Bottom-third swipe: touch handlers on the pane elements switch Answer<->Map only for a horizontal swipe starting in the bottom 1/3 of the pane over ~40px (smaller movement is a tap and passes through; composer/buttons/links/inputs excluded; top 2/3 never switches, so map drag/zoom is untouched). Desktop unchanged.
- Slim preview: #pin-preview docked at the TOP of the map shows case name, court and year with Read and Source. Read expands the strip downward in place with the scrollable full text; Source opens its Sources card. Map/outside click or Escape closes it; a drag never opens it. Map pins reach it through a new optional Docs3D.onCiteTap hook in static/map3d.js; with no hook set, v1/map pin behaviour is unchanged.
- No visible numbered badges on answer citations or map pins (linking preserved, per #95). Manual-test note for the swipe added to docs/FRONTEND_INVENTORY.md.

OSS considered: no new library. The pane/tabs, gesture and preview are plain HTML/CSS/vanilla JS in the existing v2 files, reusing the existing Docs3D map API and sheet components; a touch/gesture or component library (e.g. Hammer.js, shadcn) does not fit the repo plain-HTML/no-new-deps rule.
