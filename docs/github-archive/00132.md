# Issue #132: Voice and tour: a named speaker, visible audio states, and the v1 walk

- State: open
- Opened by Pukujan on 2026-10-19
- Original: https://github.com/Pukujan-lab/arize-ai-hackersprint/issues/132

The voice and the tour do not match v1. Evidence is in `docs/issues/2026-10-19-map-voice-retrieval-regressions.md` (sections B8–B12).

**Observed on the deployed build `f7e87bf`:**
- The tour transcript is a bare line of grey text with no speaker name, no speaking indicator and no sign that the page is talking to the reader.
- A slow or failed clip is silent: the narrator gives up after 7 s or on an error and advances on a timer with no message. There is no browser-speech fallback and no "audio unavailable" state. `Audio loading…` exists only in the memo header, not on the map.
- Cached answers are marked in the memo's `Answer status` line but not on the map or in the tour.
- Opening a saved run, or opening `/map`, never narrates and never starts the tour. Only a freshly asked question calls `listen()`.
- The tour walks authority pins only. The summary, the source reasoning, the opinion and the memo are not stops; v1 spoke the summary first, then the sources and citations, then the opinion and the memo.
- The caption shows a whole stop at once, so it does not follow the voice.

**Must instead:** a named speaker and live indicator while the page speaks; `Audio loading`, an unavailable-voice fallback and a cached-answer marker in the same place; any opened run narrates and tours; the walk is summary → sources/citations → opinion → memo → authority stops; the caption advances with the audio and the current pin is highlighted.

Acceptance tests and spec outcomes (`O86` onward) land before any application code changes.
