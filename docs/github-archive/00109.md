## Summary

Alex's rule from the handoff (#104): ABA builds the app; the other agents own issues, specs, docs, verification and coordination. The repo contradicted that — `contracts/agents/coding-agent.json` granted ABA write access to `docs/`, `contracts/`, `tools/`, `.github/`, `acs/*` and the requirements files, and it declared an `acs-board` write.

- `contracts/agents/coding-agent.json`: write paths reduced to `app/`, `static/`, `schema/`, `migrations/`, `tests/`, `server.py`; `acs-board` write removed; rules state ABA runs on the MacBook Pro, never files or edits issues, receives an already-filed issue number, never writes docs/contracts/CI, and never adds dependencies.
- `AGENTS.md`: new **ABA scope** section; the ACS claiming section now says board claims belong to the coordinating agents.
- `.github/PULL_REQUEST_TEMPLATE/aba.md`: scope line under the intro.
- `docs/V2_CHECKPOINT.md`: "Hard rules for builders" states ABA's remit.

No CI check is added. A PR-body text match was tried and dropped: it false-positived on any PR that mentioned the phrase, and an ABA PR could evade it by omitting the line. The boundary is enforced by ABA's contract and its own build gate, not by a string match here.
