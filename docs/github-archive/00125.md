## What changed

- `web/` is the frontend: four routes (`/`, `/map`, `/observability`, `/slides`), one navigation, the memo and composer, the rewritten map, the narrated tour and the deck.
- The cutover is complete. Every page comes from `web/dist`, and nothing falls back: with no build, each address returns 503 with no page body (`tests/test_retired_routes.py`). `/v1`, `/v2`, `/dashboard` and `/guide` answer 308 with an empty body. `static/` is deleted in full, and `tools/shots*.py` and `tools/video.py` went with it because they drove controls the old pages owned.
- The device session id moved into the build (`web/src/lib/session.ts`): a stable per-device id on every same-origin `/api/` call, so `/api/runs` still returns the runs this device asked for. Without it the Observability page would have been permanently empty in production.
- The logo and share card are served from the build (`/logo.svg`, `/og.png` from `web/dist`), and the sitemap lists only the four surviving pages.
- The map is a rewrite, not a wrapper: pre-projected state and Colorado county geometry copied into `web/public/vendor`, citation pins, typed links, basemap toggle, legend and the `window.__precedentMap.v1` debug contract. The vendored d3 bundles carry their SHA-256 prefix in the filename.
- `deploy/deploy.sh` and CI pass the commit into the build so the built bundle can report it (the deploy host builds from an archive with no `.git`).
