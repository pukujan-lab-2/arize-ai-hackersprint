# PR #5: InferHub: no more empty answers from reasoning models; Octo timeout 5s

- State: merged (2026-10-17)
- Opened by Pukujan on 2026-10-17
- Original: https://github.com/Pukujan-lab/arize-ai-hackersprint/pull/5
- Branch `fix/inferhub-empty-content` into `main`, +64 −6 in 3 files, merge commit 684e52f51cb60ad44ba8ac28d5e528493fa97270

**Problem:** `cb/deepseek-v4.1-flash` spent all 400 max_tokens on reasoning and returned empty content, so every answer silently fell back to the template (no llm_error logged). Octo live search (~1.9s warm) sometimes missed the 2.5s timeout on a cold first call.

**Fix**
- `_inferhub`: `max_tokens` >= 2000 plus `thinking: {type: disabled}` (verified on InferHub: 0 reasoning tokens, ~3s). If content is still empty while reasoning is present, retry once with a non-reasoning model (`kiro/claude-haiku-4.5`, override with `INFERHUB_FALLBACK_MODEL`; primary via `DEFAULT_MODEL`).
- Empty content after the retry raises `EmptyContent`, which is recorded in `LAST_ERR` so the run gets an `llm_error` event. `complete()` logs a warning whenever it falls back to the template.
- The provider string now names the actual model, e.g. `inferhub/cb/deepseek-v4.1-flash`.
- `octo_retriever`: live timeout raised from 2.5s to 5s.
- Test-first: `tests/test_llm_inferhub.py` (retry on empty+reasoning; template fallback is logged).

**Verified:** tests/test_llm_inferhub.py, test_empty_graph.py, test_demo.py: 6 passed. A follow-up meets all of test_followup's assertions.
