# PR #17: Move the backend into app/ and add a repo manifest, agent contracts and writing-helper pin

- State: merged (2026-10-17)
- Opened by Pukujan on 2026-10-17
- Original: https://github.com/Pukujan-lab/arize-ai-hackersprint/pull/17
- Branch `chore/repo-layout` into `main`, +2884 −680 in 76 files, merge commit 07b6d96ffe886b13d696e374e1bda05e608f9f54

The backend used to sit as 17 loose modules at the repo root, next to seven docs and two scripts. This PR moves it into an `app/` package and gives agents a written map of where everything lives, so the next agent doesn't have to guess.

**What moved.** Every move is a `git mv`, so `git log --follow` still works.

- The backend modules (server, llm, agents, graph_store, octo_retriever, limits, stats, tracing, seo, coord, contracts, ttschain, octocache, build_octo_snapshot, load_surreal) are now in `app/`. Imports read `from app import llm`. Every runtime path (`cache/`, `runs/`, `data/`, `static/`, `.tts_cache/`) still resolves to the repo root, and `GRAPH_DATA_DIR` still overrides `data/`.
- `acs_board.py`, `acs_claim.py` and `acs_hotload.py` are now `acs/board.py`, `acs/claim.py` and `acs/hotload.py`, next to the vendored ACS runtime.
- The docs and `issues/` moved to `docs/`, and `ci_local.sh` and `run_all.sh` moved to `tools/`. `README.md` stays at the root.
- `server.py` at the root is now a two-line shim (`from app.server import app`), so `uvicorn server:app` still starts the same app. `deploy/run_app.sh` now runs `uvicorn app.server:app`. `install_launchd.sh` and `run_all.sh` match either name when they stop the old process.
- `schema/` and `migrations/` stay at the root. The deploy runs `python -m schema.migrate` and `schema.backfill` from there; `schema/backfill.py` now imports `from app import llm, octocache`.

**What agents can read now.** `repo.manifest.json` lists every top-level path with its owner, whether agents may edit it, and where its runtime data lives. `contracts/agents/` has one contract per role (planner, retriever, answer, safeguard, plus coding-agent), each with input and output schemas, allowed paths and the stores it touches. `contracts/storage.json` maps every store: the Octo legal_graph collections, the six versioned Octo app tables at schema version 3, SurrealDB, and the local fallbacks. `AGENTS.md` covers where code goes, the claim and lock process, test-first, the PR and auto-merge flow, and how to run the gates locally.

**Writing helper.** This pins content-generation-modules 0.5.12 at `6831f91e`, the same commit hades-v2 uses, without copying any of its source. The eight-module adapter is in `.content-system/`, the always-on block sits between the `cgm:always-on` markers in `AGENTS.md`, and the pin is also recorded under `pins.cgm` in `.coord/assignment.json`. The README was rewritten as a product page, and the TTS, cache and migration detail from #11 and #16 moved to `docs/voice-and-data-model.md` with only path changes.

**New CI checks.** The gates job now checks out the pinned helper into `.cgm/` and runs three checks: the adoption validator (copied from vastai-gpu-broker), the helper's adapter validator, and its HSW check. `tests/test_manifest.py` fails if a top-level path is missing from the manifest, if a contract is invalid or names an unknown store, if the storage map drifts from `schema.SCHEMA_VERSION`, or if code writes to a repo path the manifest doesn't declare. mypy now runs on `server.py app acs/{board,claim,hotload}.py`.

**Testing.** I wrote `tests/test_layout.py` first and watched it fail. Locally ruff, ruff format, mypy, compileall and the full suite pass (92 passed, 20 skipped for browser, live and data tests). The branch also boots under both `uvicorn app.server:app` and `uvicorn server:app`, and `/api/health` returns 200 on each. It imports and serves `/api/health` on the Pro's own Python 3.9 venv as well. One test fails in that venv, `test_openapi_schema_has_no_drift`. It fails the same way on current `main`: the Pro has different FastAPI and pydantic versions from CI.
