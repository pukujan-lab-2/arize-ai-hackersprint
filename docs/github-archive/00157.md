`acs/board.py::oio_record` wrote three constants into every issue-log record:

```python
"project": {"id": "Pukujan/agent-custom-setup", ...},
"content_author": "legal-graphrag-demo",
"directing_human": "alex",
```

The first makes a log about this app's own tooling claim to belong to the ACS repo, and the third invents an attribution for records nobody directed. `AGENT_GUIDE.md` asks for content author, filer origin, directing human, and destination to be recorded *separately*; a constant cannot do that.

Project and destination are now independent parameters, with env overrides so an adopter can set them without editing code:

- `OIO_PROJECT_ID` — what the log is about (defaults to `Pukujan-lab/arize-ai-hackersprint`)
- `OIO_DESTINATION_REPOSITORY` — where the record is filed (defaults to `Pukujan/agent-custom-setup`)
- `OIO_CONTENT_AUTHOR`, `OIO_DIRECTING_HUMAN`

`directing_human` is `None` unless someone is named, and `claim.py log` gains `--project`, `--destination` and `--directing-human`.

Verification: `ruff check` and `ruff format --check` pass; six tests pass in `tests/test_acs_claim.py`, including one asserting the directing human stays unset when nobody directed the log.
