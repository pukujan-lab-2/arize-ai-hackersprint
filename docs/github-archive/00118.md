## OSS considered

- **BackstopJS / Percy / Playwright `toHaveScreenshot`** — the obvious tools for "did the rewrite preserve the map". Rejected: the spec requires behaviour, not pixels (`docs/specs/2026-10-18-frontend-v3.md`, "Map parity"), and a pixel diff would fail on any legitimate restyle. `tools/parity_dump.py` records the stop order, stop text, pin groups, county heat and arc counts instead, and the new map is compared against that. Playwright is already a test dependency and is what the tool drives.
- **Doorstop / `pytest-bdd` / `behave`** — requirements-traceability and Gherkin runners. Rejected: the outcomes already live in the approved spec as numbered statements with an owner decision and a named test, so what is missing is a lint over two text formats, not a runner or a second requirements store. `tools/spec_policy.py` is ~90 lines and also enforces the no-stack-prescription rule, which neither project does.
- **`vulture`** — used as-is for the "no dead code" invariant; nothing written in its place.
