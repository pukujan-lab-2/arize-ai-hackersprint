# Issue #20: CI/CD: auto-deploy after merge (AUTOMERGE_TOKEN) + pin dependencies

- State: open
- Opened by Pukujan on 2026-10-17
- Original: https://github.com/Pukujan-lab/arize-ai-hackersprint/issues/20

## Two CI/CD follow-ups

### 1. Deploy doesn't fire automatically after merge
- Squash merges done by auto-merge with the built-in `GITHUB_TOKEN` don't trigger `push` events, so `deploy.yml` doesn't run after a merge.
- The 5-minute scheduled deploy never fired either (run 39003443409 had to be started by hand).
- **Fix:** create a fine-grained personal access token (repo: contents, pull requests, actions read/write) and save it as the repo secret `AUTOMERGE_TOKEN`. Use it in `automerge.yml` so merges trigger `deploy.yml`, or trigger deploy with `workflow_run` after `CI` succeeds on main. Then check whether the schedule is still needed.
- **Done when:** a merged PR deploys to the Pro on its own and public `/api/health` returns 200.

### 2. Pin dependency versions
- `requirements.txt` isn't pinned. The Pro (Python 3.9) has different FastAPI/pydantic versions than CI (Python 3.11), so `test_openapi_schema_has_no_drift` fails on the Pro.
- **Fix:** pin exact versions that work on both 3.9 and 3.11 (or add a lock file), regenerate `contracts/openapi.json` with `python contracts.py --write`, and reinstall the Pro venv through deploy. Optionally move the Pro to Python 3.11.
- **Done when:** the contract test passes both in CI and on the Pro.

Rules: test-first, through auto-merge; never print or commit secrets.
