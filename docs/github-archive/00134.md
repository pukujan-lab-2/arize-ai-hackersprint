# Issue #134: Retrieval: meaning, relevance, and the authorities Octo already holds

- State: open
- Opened by Pukujan on 2026-10-19
- Original: https://github.com/Pukujan-lab/arize-ai-hackersprint/issues/134

Retrieval is lexical, has no relevance floor, and discards retrieved authorities. Evidence is in `docs/issues/2026-10-19-map-voice-retrieval-regressions.md` (sections D15–D21).

**Observed:**
- `app/octo_retriever.py` joins stopword-stripped tokens with `OR` and runs one `websearch_to_tsquery`/`ts_rank` query. There is no embedding call anywhere in `app/`, although the Octo workspace holds 804,646 passages, each with a 1024-dimension `baai/bge-large-en-v1.5` embedding and an HNSW cosine index.
- No relevance floor: "hello how are you" returns 33 passages and eight citations. Run `142449-adccd3` (`am i allowed to carry gun withotu license`) returns plumbing, teaching-licence and liquor-licence cases, and `safeguard.pass` is still true.
- One typo (`withotu`) and the everyday word `gun` (not `firearm`) are enough to lose the statute.
- Five of the twelve retrieved works are dropped because the local graph has no node for them.
- The graph half ranks by global in-degree; broad titles such as "eCFR Title 29" and "26 CFR" rise above question-relevant authorities.
- Statutes arrive as `C.R.S. Title 10, Article` with no section, date, URL or passage.
- Arize tracing export fails with `StatusCode.PERMISSION_DENIED` on every run.

**Must instead:** a question phrased differently from the authority's words still finds it; an out-of-scope or unsupported question is answered with that fact and does not report a passed citation check; typos and synonyms do not break retrieval; no retrieved authority is dropped because the local graph lacks it; the graph half ranks by relevance to the question; statute citations are complete; completed runs reach tracing or the page says tracing is unavailable and why.

Acceptance tests and spec outcomes (`O93` onward) land before any application code changes.
