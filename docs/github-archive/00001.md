# Issue #1: Hosting: serve arize.design-bakery.com from the Daytona sandbox (tunnel keeps dropping)

- State: open
- Opened by Pukujan on 2026-10-16
- Original: https://github.com/Pukujan-lab/arize-ai-hackersprint/issues/1

## Problem
arize.design-bakery.com is a Cloudflare tunnel forwarding to the Daytona preview URL (`3000-hpm8ocjo7sx9gya1.daytonaproxy01.net`). The tunnel can't run inside the sandbox, so it runs on Alex's Mac (`~/cftun/run.sh`) and drops when that machine's network blips, sleeps or reboots (530 errors).

## Why not in the VM
Sandbox outbound traffic is allowlist-only. Tested from inside: TCP `region1.v2.argotunnel.com:7844` blocked, TCP `198.41.192.57:7844` blocked, `https://api.cloudflare.com` no response.

## Options
1. Ask Daytona to allow outbound 7844 to `*.argotunnel.com` (region1/region2.v2.argotunnel.com) and `api.cloudflare.com:443`, then run `cloudflared` in the sandbox under a restart loop with `--protocol http2`. Transfer the tunnel token out-of-band only (never in issues or commits) and store it with `chmod 600`.
2. Fastest: in the Cloudflare dashboard, make `arize.design-bakery.com` a redirect or Worker proxy to the Daytona preview URL, so no process needs to stay running.
3. Stopgap: make the Mac connector a launchd service.

## Acceptance
arize.design-bakery.com returns 200 for 24h without depending on a laptop.

## Security
Rotate the tunnel token after the hackathon.
