**Pukujan commented, 2026-10-17**

Approved plan from Alex (supersedes the earlier comment where they differ). Built by ABA only, test-first, one PR that closes this issue.

1. First screen is chat-only: a big input with autofocus, and 3 or 4 example chips, one of them a map-intent chip with a pin icon. No "Start here" text, no map and no tour on load. Attention goes to the input through size, contrast, whitespace, a single accent color on Ask and one subtle glow.
2. After an answer that cites located cases, an inline map card opens on its own below the summary. Its space is reserved first, a static image shows first, then it upgrades to the live map. Pin numbers match the citation numbers. "Expand" opens a split view (memo left, map right) with pin and citation highlighting synced both ways. No modal.
3. Performance: no map library on the home page at load. Load it on intent (map chip, Expand) or while the answer streams. Tour audio uses preload="none".
4. The tour keeps autoplaying after the memo finishes. The map card shows a visible "Tour · N min" control that pauses or stops it.

Acceptance tests (`tests/test_first_screen.py`, rewritten): input is focused on load and is the only form control besides the chips; 3 or 4 chips, one with a pin icon; no "Start here" text, no map, tour controls or map scripts on load; asking renders a question bubble and a cited answer with citation chips and a Listen button; a follow-up appends a second pair; the map card appears only after the answer, with reserved height, pin labels matching the citation numbers, and a "Tour" control; Expand gives a side-by-side split, not a dialog, and clicking a citation highlights its pin (and the reverse); tour audio elements use preload="none". Before and after screenshots at 390 and 1440.
