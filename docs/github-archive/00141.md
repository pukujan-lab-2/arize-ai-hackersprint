**Pukujan commented, 2026-10-26**

Second, separate cause for the CI half of this: the gates job does not fail on the lockfile, it fails because the root `pnpm-workspace.yaml` hijacks the install.

`pnpm-workspace.yaml` (added by `e6e3013`) declares `packages: - .`. The gates step runs `pnpm install --frozen-lockfile` with `working-directory: web`, but pnpm walks up, finds the workspace root, and installs the root `package.json`'s dependency set into the root `node_modules` instead of `web/node_modules`. Run 39465529057 shows exactly that: `resolved 25, downloaded 25, added 25` (the root set is maplibre-gl and its 24 transitives), then `sh: 1: vite: not found`.

Reproduced locally in the repo layout:
- `cd web && pnpm install --frozen-lockfile` -> "Done in 1.7s", no `web/node_modules`, root `node_modules/` gets maplibre-gl
- `cd web && pnpm install --frozen-lockfile --ignore-workspace` -> installs `web/node_modules`, then `pnpm build` succeeds

So the two blockers are distinct and need separate fixes:
1. **Deploy:** `web/pnpm-lock.yaml` drifted from `web/package.json`. `deploy/deploy.sh` archives only `web/` into a temp dir, so the workspace file is absent there and the mismatch surfaces as `ERR_PNPM_OUTDATED_LOCKFILE`.
2. **CI gates:** the workspace file is present, so the install lands in the wrong directory and `vite` is not found. Adding `--ignore-workspace` to the gates install step fixes it.

The deploy is the one that matters for the owner's audio question. The gates fix matters because it has been red on main since 2026-10-20 and cannot catch the next regression.

Correction to the CI half, after reproducing both paths separately.

The gates job fails for a different reason than the deploy, and regenerating `web/pnpm-lock.yaml` does not fix it. `pnpm-workspace.yaml` (added by `e6e3013`, 2026-10-20) declares `packages: - .` at the repo root. The gates step runs `pnpm install --frozen-lockfile` with `working-directory: web`, but pnpm walks up to the workspace root and installs the root `package.json`'s dependencies into the root `node_modules`. Run 39465529057 shows it: `resolved 25, downloaded 25, added 25, done in 1.1s` — 25 packages is maplibre-gl and its tree, not the app's ~66 — then `sh: 1: vite: not found`.

Reproduced in the repo layout: `cd web && pnpm install --frozen-lockfile` leaves `web/node_modules` absent and populates the root `node_modules`; `cd web && pnpm install --frozen-lockfile --ignore-workspace` installs into `web/node_modules` and `pnpm build` succeeds.

So there are two independent defects:

| Surface | Failure | Fix |
| --- | --- | --- |
| `deploy.yml` / `deploy.sh` | builds from `git archive rev web` into a temp dir, so no workspace file; `web/pnpm-lock.yaml` disagrees with `web/package.json` on maplibre-gl | regenerate `web/pnpm-lock.yaml` |
| `ci.yml` gates | full checkout, workspace file present, install lands at the root and `vite` is missing | add `--ignore-workspace` to the gates install (the root `package.json` build script already does this) |

The deploy fix is the one that ships the browser voice. The gates fix matters because gates has been red on main since 2026-10-20 and cannot catch the next regression.
