# PR #158: Tracing: report delivery to Phoenix correctly on OpenTelemetry 1.45

After #154 the live site sent spans to Octo's Phoenix (Phoenix logged `POST /phoenix/v1/traces 200` seconds after each question), but `/api/health` kept saying `no span has been exported yet`. On OpenTelemetry 1.45 (Python 3.10+, what the server runs) the exporter sits at `BatchSpanProcessor._batch_processor._exporter`, which the recorder's search of the SDK's internals never reached, so delivery was never recorded.

The recorder now wraps the exporter before the SDK takes it, so every batch is counted whatever shape the processor has inside. `_wrap_provider` is removed. Two tests added first (a delivered span flips the status to ok; a rejected batch is reported as the reason); all seven tracing tests pass on Python 3.9 with OTel 1.41 and on Python 3.12 with OTel 1.45.1. ruff and vulture are clean.

## OSS considered
No new module; this removes ~25 lines of reflection over the OpenTelemetry SDK's internals and wraps the official `OTLPSpanExporter` instead.
