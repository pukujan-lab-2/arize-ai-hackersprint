Auto-merge merges with the built-in GITHUB_TOKEN. GitHub doesn't start any workflow for events that token causes (pull_request closed, pull_request_target closed, push), so the close step from #60 never ran after #65 and #64 stayed open. The 30-minute schedule is also unreliable on GitHub.

What changes in close-linked-issues.yml:
- It also runs when a PR's CI run finishes successfully (workflow_run fires for that). It waits up to 10 minutes for auto-merge to land the PR, then closes every issue the PR names with Closes/Fixes/Resolves and ticks it off the tracker (#58).
- After that merge it starts deploy.yml on main. A manual dispatch is the one event the built-in token is allowed to start, so merges deploy without someone running it by hand.
- The pull_request closed trigger, the schedule and the manual run stay as backups.

No personal token needed. Workflow file only; no app or frontend code.

Part of #58.
