# PR #68: Dashboard loads on macOS: /api/stack works without /proc

- State: merged (2026-10-17)

/dashboard was broken on the Mac host because /api/stack read /proc/meminfo and /proc/uptime, which macOS doesn't have, so it returned a 500 and the page threw.

Built by ABA (dyad headless, iterate mode, model ih/ali/qwen3.8-flash), test-first. No hand edits to static/.

What changed:
- /api/stack reads RAM from /proc/meminfo when it exists (kB values, converted correctly), otherwise from sysctl hw.memsize and sysconf. Uptime comes from /proc/uptime or kern.boottime. If nothing can be read, it returns null instead of failing.
- /dashboard shows a short message when the numbers don't load, instead of throwing, and checks again every 15 seconds. It also escapes values before putting them in the page, and its cards no longer overflow at 1024px.
- Tests: tests/test_stack_portable.py (200 with no /proc, meminfo units) and tests/test_dashboard_page.py (no page errors on /dashboard).
