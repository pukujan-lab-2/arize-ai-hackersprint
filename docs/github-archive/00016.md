# PR #16: Octo-backed LLM answer + retrieval caches (migration 0003), stale-answer purge, Fish timeout 5s

- State: merged (2026-10-17)
- Opened by Pukujan on 2026-10-17
- Original: https://github.com/Pukujan-lab/arize-ai-hackersprint/pull/16
- Branch `feat/octo-caches` into `main`, +552 −85 in 15 files, merge commit e763fce3f8bf6f4f672c8bd042a843024f8ab631

- `octocache.py`: the shared Octo layer pulled out of ttschain. Lookups check local first, then Octo; Octo hits sync back to local; writes go to Octo in the background. Octo is used only when its schema_version matches. Run linkage via `run_context` / `run_cache_link`.
- `llm.py`: answers are cached in `cache/<key>.json` and the Octo `llm_answer` table. `stale()` rejects empty, template, reasoning-only and pre-PR #5 (`inferhub/deepseek`) answers, so they are never served or stored.
- `octo_retriever.py`: retrievals are cached in `cache/octo/<key>.json` and the Octo `retrieval` table.
- `migrations/0003_answers_retrievals.sql`, SCHEMA_VERSION 3, lock updated.
- `schema/backfill.py` runs on deploy after migrate. It is idempotent: it uploads local entries, moves stale local files to `cache/_purged/`, and deletes stale Octo rows. It doesn't touch TTS tables, and the `tts_cache` probe table is left in place.
- `FISH_TIMEOUT_S` now defaults to 5 s. The browser gives up at 8 s, so this leaves Kokoro time to answer.
- `agents.run_pipeline` sets the run id in context so cache rows link to runs.
- Tests were written first in `tests/test_octo_caches.py`: shared through Octo, sync-back, streaming path, run links, stale answers never served, backfill and purge idempotent, Octo down. Also a Fish 5 s default test.
