Closes #82

The gates run for #76 showed two faults in the new checks. Both only change warnings, so nothing that passes today can start failing.

## What changed

1. The Pro's Python 3.9 pins are audited for real now. `python tools/dep_policy.py pins --python 3.9` writes the lock pins for Python 3.9, and CI runs pip-audit on that file. Before, pip-audit read requirements.txt with the runner's 3.11 markers and skipped the 3.9 lines, so the warning never showed up. Run locally, it reports 20 advisories across anyio 4.12.1, python-dotenv 1.2.1, python-multipart 0.0.20, requests 2.32.5, starlette 0.49.3 and urllib3 2.6.3. The fixes need Python 3.10 or newer (#20). It stays a warning.
2. The SDK warning now looks only at code files (.py, .js, .ts, .sh) outside tests/. On #76 it fired on tests/fixtures/pr_policy_cases.json, a fixture that holds a provider URL on purpose.

## Tests

Written first, and they failed before the fix. There are three new fixture cases in tests/fixtures/pr_policy_cases.json: provider URLs in a test fixture, in a top-level test file and in docs, none of which are flagged. tests/test_dep_policy.py gets `--python 3.9` and `3.11` pins against the fixture lock, plus the CLI output against the real lock. The pr_policy, dep_policy and manifest tests pass locally, along with ruff and the OIO and CGM validators.

## OSS considered

No new module. Both are small fixes to the glue added in #76.
