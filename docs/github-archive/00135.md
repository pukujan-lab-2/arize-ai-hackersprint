# Issue #135: Follow-ups: generate them, make them clickable, and surface the next-question actions

- State: open
- Opened by Pukujan on 2026-10-19
- Original: https://github.com/Pukujan-lab/arize-ai-hackersprint/issues/135

Follow-ups are a dead end end to end. Evidence is in `docs/issues/2026-10-19-map-voice-retrieval-regressions.md` (sections E22–E23).

**Observed on the deployed build `f7e87bf`:**
- `web/src/pages/Index.tsx:349` reads `result?.followups`, but the result dict built in `app/agents.py` has no `followups` key. The panel always renders "No follow-up questions were recorded for this run."
- Even if one were shown, each is a plain `<li>` with no click handler.
- `Follow-up` and `New question` sit inside the memo menu drawer. The composer button always says `Ask`, so nothing tells the reader they are in a conversation.
- `Run info` shows the previous run's id instead of the run being read.

**Must instead:** every completed run carries three follow-up questions grounded in its authorities; a follow-up is a button that asks it with the current run as context; after a run the composer says it will ask a follow-up, and one control starts a new question; `Run info` names the current run.

Acceptance tests and spec outcomes (`O100` onward) land before any application code changes.
