- State: closed (2026-10-17)

## Objective
Make the frontend inventory and the API contracts easy for every coding agent to find, so v2 UI work starts from what the code actually does instead of guesses.

## Inputs
- `static/*.html` and `static/*.js` (index, map, dashboard, observability, guide, slides; navbar.js, declutter.js, firstscreen.js, followup.js, links.js, voice.js, map3d.js, map3d.co.js)
- `contracts/openapi.json`, `contracts/agents/`, `docs/UX_GUIDELINES.md`, `AGENTS.md`

## Outputs / acceptance
- `docs/FRONTEND_INVENTORY.md`: one section per HTML page route, listing buttons, links, nav items, drawers/collapsibles with element id or aria-label, owning file, and API routes called.
- `static/map3d.js`, `static/map3d.co.js` and the vendored county/state data are marked KEEP AS IS (the 3D map and tour stay; v2 rebuilds the UI around them).
- A "Known clutter" section listing duplicate or noisy UI.
- A "Read first" section in `AGENTS.md` and a pointer in `contracts/agents/coding-agent.json` linking the inventory, openapi.json, contracts/agents/ and UX_GUIDELINES.md.
- `tests/test_frontend_inventory.py` fails when an HTML route in openapi.json has no section in the inventory; runs in existing CI.
