test_memo_then_tour.py::test_slow_memo_is_not_dropped_at_8s failed on main. The cause is the test browser, not the page.

What I found:
- Plain Chromium (Playwright, on the Mac host), with none of our code loaded, starts a 1-second WAV, then its clock stops at 0.064 s. The clip never ends. This happens with or without the 12-second delay.
- With `--disable-audio-output` the clock runs, `ended` fires, and every audio test passes against main's static/audio.js, unchanged.

So the fix is one flag in the shared browser ARGS in tests/test_audio_loading.py, which test_memo_then_tour.py imports. No app or frontend code changes.

ABA was run on this issue first (dyad headless, ih/ali/qwen3.8-flash). It passed the gate by adding a stall watchdog to audio.js that jumps a stuck clip to its end. That hides the stall instead of fixing it, so I didn't ship it.

Local: `pytest tests/test_memo_then_tour.py tests/test_audio_loading.py` gives 15 passed, 4 skipped (live-only).
